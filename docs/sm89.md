# Ada (SM89) sparse attention

Tier 0's `13-sm89-attention.patch` enables DeepSeek V4 attention on compute
capability **8.9**. `serve.sh` accepts Ada automatically. The backend selects the
fallback by the current device's capability; SM90, SM100 and SM120 retain their
existing attention paths. This is not a fallback for arbitrary older GPUs.

The patch skips FlashMLA metadata creation and its SM90+ sparse-prefill path on
Ada. It reuses SGLang's dual-scope Triton kernels to attend over the sliding
window and compressed rows in one online softmax, including the attention sink.
Queries and probabilities use BF16 tensor-core products with FP32 accumulation.
For query shapes outside the dual-scope wrapper's contract, it uses SGLang's
portable separate-scope Triton implementation.

SM89 retains the **V4 584-byte cache layout**: FP8 non-RoPE values, BF16 RoPE,
and UE8M0 scales. The new SM100/SM120 V41 and V41_FP4 formats are not enabled on
Ada; interpreting their bytes with this kernel would be wrong. Unsupported
cache formats fail explicitly. This port does not establish parity with the
checkpoint's released V4.1 KV arithmetic.

At recipe `00fd12a`, tier 1 host-KV reads each pool's own data, scale and padded
page geometry, including V4. Ada now inherits its upstream default: the pool
covers the context, with compressed KV beyond the GPU budget in host memory.
`SGLANG_DSV41_HOST_KV=0` remains an explicit opt-out. The earlier Ada-only opt-out
was needed for the fixed V41_FP4 gather at `8719948` and has been removed.

## Workspace and launch policy

- Fixed `BLOCK_H=16, BLOCK_N=64, num_warps=8`: no runtime autotuning.
- `SGLANG_SM89_ATTN_SPLITK=auto` uses eight splits through four query rows,
  four splits through eight rows, then the unsplit kernel. `0`, `2`, `4`, `8`
  force a split choice; `file` follows the upstream dual-scope heuristic.
- `SGLANG_SM89_ATTN_ROWS=1024` bounds prefill query chunks and the portable
  fallback's intermediate allocations. It must be positive. This is workspace
  chunking inside attention, not a scheduler yield point.
- Split-K buffers are allocated per call, like the output and LSE buffers.
  PyTorch's graph allocator owns them during capture; there is no global scratch
  cache shared by independently captured graphs.
- `SGLANG_SM89_ATTN_DUAL=0` forces the portable separate-scope path for comparisons.
- Forcing split `8` with 1024-row chunks needs about 1 GiB of FP32 partial outputs;
  prefer `auto`, which uses the unsplit kernel for those chunks.

## Current validation at recipe 00fd12a

Canonical A-r8 ran the default tier-1 feature set on one experimental 32 GiB
RTX 4080 SUPER (SM89), dual EPYC 7543 and all eight physical NUMA nodes with
56 pinned expert workers. It passed the exact `tools/check.sh`, ten component
diagnostic groups, all five `tools/tool-call-check.py` cases, fixed-corpus
quality screening, and sequential 4K/16K/35K retrieval. The 49 affected
SGLang Python files matched the pinned recipe after execution. The campaign
used strict local native expert allocation, a 440 GiB memory cap with zero
scope swap, an exclusive GPU, verified input-storage adapters, prepared
FlashInfer cache, normal prefill calibration and a bounded ordinary-file-cache
trim before client requests. The measured client window had no new
memory.max/high/OOM/swap event. These conditions are part of this result.

The checkpoint reference was authenticated and reused after fresh preflight;
the served scores were collected from A-r8. All 24 pieces had 479 finite,
exactly input-ID-aligned scored positions, 11,496 total. Mean NLL was
**0.714111** for the reference and **0.715096** for serving, a paired mean
change of **+0.000985 ± 0.004106 nats/token** (piece standard error).
Per-token scores differ, so neither numerical identity nor broad quality
equivalence is claimed.

| Stock `tools/bench.py` workload | A-r8 observation |
|---|---:|
| Four default Japanese decode prompts, median completion rate | 31.0 tokens/s |
| First fixed 35K-token prefill probe | 41.63 s; 841 tokens/s |
| Second fixed 35K-token prefill probe | 29.65 s; 1,180 tokens/s |
| Six `--other-text` decode prompts | 24.7–28.1 tokens/s |

Decode rates include prompt work in client wall time. The fixed-seed 35K
random-ID probes measure transport/prefill latency, not language quality;
keep the first and second observations separate. The 12-chunk WikiText
screen had mean NLL 0.898446 over 12,276 scored positions, a different corpus
from the checkpoint comparison. [Current-result JSON and individual rows](benchmarks/sm89-00fd12a-20261024.json)
include source/configuration hashes and raw-tool-output references.

The server configured a **1,048,576-token** context and left tier-1 host-KV
enabled by default. Its allocated compressed pool fit wholly on the 32 GiB
GPU (C4 physical and logical rows both 262,144; C128 GPU rows 8,192).
Neither host-KV staging nor a 1M-token request was exercised; the longest
checked retrieval prompt was 34,971 tokens. This PR does not include the
separate hot-slot/GPU-glue treatment. It enables Ada but does not claim a
speedup over an unmodified recipe, which cannot serve SM89.

The context-only first-hunk adjustment to patch 13 also applies across the
newer `8b9f7241` SGLang pin without changing any of the 49 files in the
tested `9c0f6d6a` runtime. That newer merged runtime has source/CPU checks
only; the A-r8 numerical and performance evidence remains specific to
`00fd12a` and SGLang `9c0f6d6a`.

## Historical validation and numerical screening

- Both portable and dual arms passed all **76 full-model checks**: basic facts,
  exact JSON/arithmetic/Unicode, concurrent multi-turn conversations, parsed
  tool calls and results, aligned/repeated input logprobs, the retrieval cases
  above, and concurrent throughput requests.
- All **399 GPU fixture checks** passed on the new pinned runtime: padded V4
  pages and FP64 reference, masked/ragged rows, sinks, eager/replay equality,
  updated graph inputs, fixed-unsplit batch invariance, and concurrent replay
  of independently captured graphs.
- The older 29-patch stack applied in tier order. Those counts describe the historical package, not current-default acceptance.

The first portable attempt hit a streamed-prefill compilation timeout and an
incorrect client assumption about SGLang's unscored logprob boundary sentinel.
That failed evidence was retained; the table uses a complete corrected, warmed
rerun. An interior null, wrong token ID or non-finite logprob still fails.

Numerical identity with portable attention is not claimed. One online softmax,
BF16 probability rounding and split reduction change arithmetic. The split
policy also changes reduction order with batch row count; use split `0` for
fixed-unsplit batch-invariance checks. Full-model checks do not establish
general quality equivalence or equivalence to the released V4.1 KV format.

A separate fixed WikiText-2 screening sample scored **12,276 token positions**:
mean negative log-likelihood was **0.894495 → 0.897459 nats/token** and sample
perplexity **2.4461 → 2.4534 (+0.30%)**. The mean increase of 0.002964 was below
the aggregate 0.02-nat threshold declared before collection. Per-chunk signed
changes ranged from −0.0169 to +0.0215 nats/token; mean absolute token-score
differences ranged from 0.080 to 0.134, with a maximum individual difference of 9.25.
This is not a full WikiText evaluation or a quality-equivalence result. Both quality
arms enabled the same optional CPU/GPU glue bundle; the 76-check runs and speed
table above were measured separately without it. Short logprob probes were
bit-identical with/without that bundle in each attention mode.

An independent FP64 comparison also checked first/middle/last query rows from
**80 captured real attention calls**, rerunning each subset with split `0` and
split `8`. Both modes passed a rounding-aware error check: after accounting for
each element's unavoidable nearest-BF16 rounding error, the worst remaining
absolute error divided by per-head row RMS was **0.01921**, below 0.02. Mean
absolute error was lower than portable attention on both capture sets. The
original absolute row-RMS bound was corrected because even ideal nearest-BF16
outputs could not meet it on the observed large coordinates; its failed reports
were retained. These checks isolate attention arithmetic, not whole-model parity.

Per-chunk quality statistics, configuration, and numerical-check details are in
`benchmarks/sm89-quality-20261023.json`.

## Reproduce validation

To reproduce the maintainer-requested acceptance at `00fd12a`, first run the checkpoint
reference without a serving process on the GPU. Then run the launch smoke check,
which starts and stops its own server, before starting the server for the
remaining clients. Use the normal tier-1 features and launcher defaults; record
any hardware-specific adapter, affinity or environment override explicitly.
The tools below are separate GPU/server stages, not concurrent jobs.

```sh
mkdir -p results
.venv/bin/python tools/ref-nll.py /path/to/checkpoint results/ref.json
MODEL=/path/to/checkpoint tools/check.sh
MODEL=/path/to/checkpoint ./serve.sh --background
# Wait for the server readiness message before running the clients.
.venv/bin/python tools/tool-call-check.py http://127.0.0.1:8080
URL=http://127.0.0.1:8080 .venv/bin/python tools/nll.py score /path/to/checkpoint results/served.json
.venv/bin/python tools/nll.py compare results/ref.json results/served.json
.venv/bin/python tools/bench.py --url http://127.0.0.1:8080
.venv/bin/python tools/bench.py --url http://127.0.0.1:8080 --other-text
```

Create the result directory first, retain complete outputs and server logs, and
stop the owned server after the client stages. A 1M configured pool does not
itself prove that any KV reached host memory; report the pool split and whether
host staging ran. The reference comparison scores the same 24 fixed Japanese
and English pieces and reports its standard error across pieces. The historical
WikiText screen below uses different text and cannot replace it.

After `setup.sh` applies the patch, on an idle SM89 GPU:

```sh
python3 tools/test_sm89_dispatch.py third_party/sglang
python3 tools/sm89_validation/test_logprob_alignment.py
.venv/bin/python tools/sm89-attention-test.py --gpu --no-timing
```

For the full-model client, start each arm separately with the same checkpoint,
CPU layout and fixed placement. Use 64K context and token pool, chunk size 2048,
four active requests, graphs on, and speculation off. Set the served name and
port to match the client (or override its flags). Use
`SGLANG_SM89_ATTN_DUAL=0` for the portable arm and `=1` for the dual arm.
Record all launch settings, source revisions and host adapters alongside results.

```sh
# Run against each corresponding server, using fresh output directories:
python3 tools/sm89_validation/model_client.py --arm portable --output results/portable
python3 tools/sm89_validation/model_client.py --arm dual --output results/dual
python3 tools/sm89_validation/model_client.py --compare results/portable results/dual
python3 tools/sm89_validation/summarize_runs.py results/portable/report.json results/dual/report.json --output results/performance.json
```

The client retains every HTTP exchange, token IDs, logprobs and throughput trial.
`tools/sm89_validation/README.md` describes its exact judgments and limitations.
The optional fixed WikiText screen downloads public text separately:

```sh
python3 tools/sm89_validation/fetch_quality_corpus.py
.venv/bin/python tools/sm89_validation/quality_probe.py --checkpoint /path/to/checkpoint --arm portable --output results/portable-quality
# Repeat against the dual server, then compare the reports:
python3 tools/sm89_validation/quality_probe.py --compare results/portable-quality/report.json results/dual-quality/report.json --output results/quality-comparison.json
```

The quality tool checks a content hash of fixed row IDs/text, uses the checkpoint
tokenizer without a chat template, and scores up to four complete 1024-token
chunks per excerpt. It is a fixed screening sample, not a full WikiText benchmark.
